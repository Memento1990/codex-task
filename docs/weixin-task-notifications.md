# 微信日常任务通知与数据库副本恢复

## 微信正式渠道

在「消息通知 → 微信 · 连接与日常通知」扫码，使用同一微信账号向机器人发送一次性绑定码。完成绑定后明确启用微信任务通知，并开启「外部通知」总开关。默认订阅任务完成与卡点出现，可另选卡点解除。关闭桌面浮窗通知不会关闭外部渠道。

正式凭据与 DEV 连接实验室完全独立，不会自动导入实验室账号。凭据使用当前 Windows 用户的 DPAPI 加密。二维码在本机编码，不加载远程二维码图片。只接受扫码账号向指定机器人的非群聊文本绑定码；收到的消息不会执行命令。

建立基线之后观察到的任务变化进入持久化发送队列；启动、重新启用时先建立当前基线，不补发此前历史。渠道从停用变为启用时，会保守地重建共享基线；其他已启用渠道也可能略过这一轮观察前的变化，避免将启用前事件发给新渠道。已启用且绑定的账号在重启后恢复连接。发送内容可能包含任务标题、卡点标题；请勿在标题中放敏感信息。

发送记录中的「平台已受理」不代表手机收到或已读。微信请求结果不明确或发送进程中断时标记「结果未知」，不自动重发，以避免重复。微信会话可能到期或被平台限制；长期空闲、平台限流以及永久主动通知能力不作保证。应先发送一次明确确认的测试，并在手机核对。

这是本地 GUI 后台通知服务，不是 Windows 常驻系统服务；退出、休眠、断网会影响通知。不能替代紧急告警渠道。

## 数据库检查与副本恢复

设置中的「数据库检查与副本恢复」只处理独立副本。原数据库、WAL、SHM 不以 SQLite 打开，不删除、不重建、不替换，也不停止旧版 Reporter 或 Codex。检查操作也会创建证据副本。

每次结果保存在当前数据目录上级的 `control/database-recovery/<UUID>/`：

- `source-copy/`：原始文件字节副本；
- `report.json`：哈希、稳定性、完整性与恢复计数；
- `analysis/`：可丢弃的分析副本；
- `recovered-data/events.sqlite3`：仅在验证成功时提供的独立恢复库。

复制前后及副本哈希必须一致，才能进一步分析。但哈希一致仍不是与所有写入者协调的事务快照。文件正在变化或被 Windows 字节锁定时安全拒绝；等相关会话正常退出后再试，不要强杀进程或删除 WAL。

恢复仅保留验证通过的最新任务快照，清除无法验证的运行态和计时；从当前已完成任务快照重建确定性完成记录。不会恢复完整历史事件、历史完成轮次或耗时，也不会编造这些数据。报告中的未知数量为 null，所有恢复均标记为部分恢复。

当前不提供「直接应用恢复库」：历史写入进程无法可靠协调，直接替换可能造成再次损坏。成功创建副本不表示当前看板已恢复；当前看板仍使用原目录。

## 发布与验证范围

本功能开发不自动发布、不安装到正式目录、不修改正式用户数据库。自动化测试使用临时模拟账号、模拟传输和数据库损坏夹具；真实扫码、平台送达与长期会话仍需显式人工验证。

2026-11-04 本地验证：前端 36 项测试、Rust 核心 139 项测试通过，原生工具窗权限与工作区尺寸 2 项测试通过。隔离 DEV 原生冒烟验证了正式微信入口可见、默认离线且未启用、检查独立数据库副本、恢复前确认与取消，以及拒绝直接应用恢复库；没有扫码、绑定或发送外部消息。回归覆盖任务库损坏时独立发送队列仍可处理、启用基线抑制，以及迁移前等待通知调用和网络操作安全结束。
