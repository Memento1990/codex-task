# 方案 A 还原落地约定

## 目标与基准

用户已选定 `designs/redesign-v2/a-inspection-matrix.html` 及其共享交互样式作为视觉与布局基准。
覆盖主窗、392px 窄窗、行内三栏详情、右侧完整详情抽屉、头像球、通知及全部工具窗，
并保留搜索、命令键盘导航、完成记录分页与真实功能的操作闭环。
原型的外壳、底部九屏导航、场景选择、模拟数据和模拟成功结果不进入正式运行界面。

## 已确认的取舍

- 任务始终由 Agent 汇报驱动。推进、解除卡点、确认等待、添加证据、重新打开等人工演示动作只用于隔离验收；真实界面提供查看、复制和看板内定位。
- 新安装默认 980×680、暗色；最小 392×570。已有用户保存的窗口尺寸、位置和主题保留，中间尺寸响应式适配。
- 设置即时保存；保存失败恢复原值并显示错误。迁移、接入变更、修复、安装等仍有各自确认与实际校验。
- 飞书签名密钥、接入诊断等额外字段放入高级配置或详情；操作时展开必要确认和实际结果，保持 A 主体布局。
- 纯 Hook 会话不进入任务统计和列表。“未汇报”只包含已有计划、尚未完整汇报的任务。
- 证据直接交由系统默认应用打开受支持的真实文件或网页；无效引用显示失败，保留复制入口。
- 暗色、顶部统计、44px 任务行、行内展开优先于通用 UI 默认规则。任务隐私、计时真实性、开发隔离与原生回归约束继续生效。

## 真实能力与原型差异

保留原生系统最小化、独立头像收起按钮、关闭到托盘和非抢焦点通知。
主窗内抽屉不复用旧版“收起详情并将窗口压至392px”动作。
修复入口按 A 提供独立工具窗，并沿用真实修复状态机与权限约束。
接入回执不代表实时在线；更新在 DEV 保持宿主限制；迁移和修复以真实后端结果为准，
不得将原型模拟 Dry run 或 Mock PASS 当作实际成功。
缺失时间保持未知，耗时沿用累计 Timer 和 partial，证据时间表示首次记录而非实际产出时间。
仅从已有最小业务事件投影需要的字段，不恢复聊天/工具动态历史。

## 实施与验收

1. 真实数据适配与视图组件 → 校验状态统计、历史归档、计时与缺失数据。
2. A 布局与工具窗落地 → 校验980×680、392×570及中间宽度；抽屉、搜索、键盘、内滚动和浅色主题。
3. 原生窗口与即时设置 → 校验尺寸恢复、工具窗权限、头像收起恢复、设置成功/失败及真实确认流程。
4. 同一合成数据、相同逻辑时间/尺寸/DPR对照原型与应用 → 保存截图、叠图/差异图并实际视觉检查。
5. 前端单元/类型构建、Rust核心和宿主测试、Win32 CreateDesktop独立桌面原生回归 → 记录初次失败、最终结果及资源清理。

截图不能替代行为验证。CDP无法覆盖的真实输入、系统焦点、托盘、拖动和跨屏行为单独报告，
不得默默切到用户输入桌面测试。必要DEV标识、当前真实版本、系统外阴影等差异单列说明。
用户后续补充授权：全部完成并验收后直接提交、推送并发布 GitHub 新版本，可作大版本升级；
按 `docs/releasing.md` 和 `app/desktop/publish-release.ps1` 先准备、核验，再发布。
发布授权不包含替换正式安装或改动正式数据。

## 后续

按以上已确认范围实施；若新发现的约束将改变原型呈现或用户操作，再向用户说明具体差异后选择。
