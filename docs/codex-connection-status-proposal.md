## 原则

配置写入、Codex授权、真实连接回执和任务同步是不同事实。工具不能直接从“配置已写入”推断用户已授权，也不能从没有回执推断未授权或未载入。MCP initialize证据不是实时心跳，使用“已确认过连接”而非“在线”。

## 推荐呈现

主状态与细节分开，主标题不再笼统写“等待Codex载入”。

| 已知事实 | 主标题 | 说明及下一步 |
|---|---|---|
| 未写入 | 尚未配置 | 按钮：配置Codex接入 |
| 完整配置，无真实回执 | 配置完成 · 连接待确认 | 本工具配置已写入，尚未收到Codex回执；这不代表未授权。若已在Codex授权，请在Codex新建/继续一次真实会话，再刷新状态。不强制用户反复授权或重启。 |
| MCP initialize有效 | 连接已确认 · 等待会话事件 | Codex曾加载此连接组件；尚未观察到本次接入的会话事件。空闲不算异常。 |
| 真实Hook有效 | 会话事件已收到 | Hook链路已确认；没有任务汇报时显示“任务同步尚未验证”，不是未接入。 |
| 同会话真实汇报已入库 | 接入与任务同步已验证 | 展示最近证据时间，不承诺当前实时在线。 |
| 配置冲突/部分缺失 | 配置需要检查 | 单独展示问题，不用“等待载入”掩盖错误。 |

详情采用四行证据清单：配置写入（可确定）；Codex授权（工具无法直接读取，请在Codex确认）；连接组件回执（时间）；Hook/进度入库（时间）。

“连接组件有更新”作为独立提示，不覆盖已确认的连接状态。任务同步未验证不应把工具栏连通图标显示为断线。不要提供伪造任务或本机preflight冒充真实连接的按钮。

## 已确认的源码问题

bridge::decorate_connection原先对upgrade_available无条件返回awaiting_reload，即使有效MCP/Hook回执存在也遮住连接事实。开发源码已去掉这个优先级，仍对partial/conflict保持失败保护，增加回归测试。
