# 微信连接验证（DEV）

此功能仅用于验证腾讯微信 Bot 协议与看板通知需求的兼容性，不是正式微信通知渠道。

## 隔离边界

- 仅在 `dev-isolated.ps1 -CodexMode isolated` 启动的 DEV 实例中，通过独立「微信连接验证 · DEV」窗口开放。正式窗口不能直接调用验证命令。
- 不安装或修改 OpenClaw，不读取 OpenClaw 微信凭证，不接入任务事件。
- 验证操作不改动正式安装、生产连接或已有 Reporter 会话；发布本模块不代表正式开放微信通道。
- 登录及会话凭证存储在 DEV control/weixin-lab 独立目录，使用当前 Windows 用户 DPAPI 保护。二维码为本地编码，无外部二维码生成服务。
- 启动与恢复默认离线；用户明确操作才开始微信网络请求。扫码成功不等于已绑定，更不等于长期主动推送可用。

## 用户验证顺序

1. 在 DEV 的更多操作菜单选择「微信连接验证 · DEV」。
2. 点击开始连接，用微信扫码并按提示确认或输入验证码。二维码旁始终提供「刷新二维码」；若手机先提示过期，无需等待页面倒计时结束即可刷新。
3. 开始收件人绑定，将一次性绑定码从扫码账号的微信会话发给 Bot。
4. 页面确认绑定后，点击测试，阅读并确认真实发送提示。
5. 在手机核实收到测试文本；API 接受请求不等于手机实际送达。
6. 正常退出 DEV 再重开，手动恢复，确认绑定状态及文本发送能否继续工作。
7. 再隔一段时间手动测试。不要据此假定永不过期的主动通知能力。
8. 测试结束可断开并清除本地连接。此操作不等于服务端撤销全部授权。

真实登录、绑定、手机收件和长时间后主动发送需要用户在场，自动测试不代替这些验收。

## 协议来源

审查来源为 `@tencent-weixin/openclaw-weixin-cli@2.1.4` 与 `@tencent-weixin/openclaw-weixin@2.4.10`，仅下载解包检查，没有执行安装器。参考：https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md 。

公开文档说明客户端行为不等于完整服务端契约。重点待验证：会话 context_token 的发送要求、无新入站消息时主动发送是否允许、失效恢复及频控。没有依据设定或承诺固定 24/48 小时窗口。
