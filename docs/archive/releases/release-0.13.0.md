# Codex Floatboard v0.13.0

## 微信日常任务通知

- 个人微信从 DEV 连接实验室扩展为正式消息通知渠道；无需 OpenClaw。
- 在「消息通知」扫码，使用同一账号向机器人发送一次性绑定码，再明确启用微信渠道与外部通知总开关。
- 默认订阅任务完成与卡点出现，可选卡点解除；发送内容包含任务标题、卡点标题及事件提示，请勿在标题中放敏感信息。
- 正式凭据与实验室账号独立，使用当前 Windows 用户 DPAPI 加密，不自动导入实验室凭据。
- 已启用且绑定的账号可在应用重启后恢复。启用先建立任务基线，不补发历史；共享基线重建可能保守略过其他渠道同一轮变化。
- 持久化发送队列使用稳定消息标识；微信结果未知不自动重发，避免重复。平台受理不等于手机送达或已读。
- 修复任务数据库损坏时阻断微信连接恢复和独立测试队列的问题；迁移前等待通知操作安全结束。

## 数据库检查与副本恢复

- 设置中新增独立副本检查、恢复前确认和恢复报告入口。
- 仅复制原数据库、WAL、SHM 后分析，不以 SQLite 打开原库，不删除、不重建、不替换原数据，也不停止现有 Codex/Reporter。
- 对复制前后及副本哈希进行一致性检查；活动写入、锁定、异常路径或超限时安全拒绝。
- 仅恢复可验证的最新任务快照，并验证新库完整性。所有恢复均标记为部分恢复，不编造历史事件、历史完成轮次或耗时。
- **不提供运行中直接应用恢复库。创建恢复副本不等于当前看板已恢复；原库异常仍需独立、安全地规划接管。**

## 发版自动化

- 增加可复用的 GitHub 发版脚本，串联测试、独立构建、签名打包、校验、明确提交范围、打标与发布。
- 默认准备阶段不推送；发布阶段需显式执行。拒绝覆盖已存在标签/资产，不接触正式安装和用户数据。

## 验证与限制

- 前端 36 项、Rust 核心 139 项、原生窗口权限/尺寸策略 2 项测试通过；Windows release 构建及隔离 DEV 冒烟通过。
- 本轮真实平台扫码及手机收件未执行；测试使用模拟传输，先前实验室收件验证不替代正式渠道验收。
- 微信会话可能受长期空闲、平台策略、限流影响；不保证永久主动通知。GUI 退出、休眠或断网会影响投递，不能替代紧急告警。
- 更新仍需明确确认安装；本发布不自动替换用户数据库，不包含凭据或恢复副本。
