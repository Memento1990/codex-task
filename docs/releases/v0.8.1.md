# v0.8.1 — 更容易恢复、升级和验证的 Codex 接入

## 使用方式

1. 完整解压，将 GUI 与 Reporter 两个 EXE 保持同目录，打开看板。
2. 在 **更多 → Codex 接入** 点击唯一的主按钮 **连接 Codex**。首次连接会在当前用户目录安装小型 Rust 组件，无需管理员权限，不修改项目。
3. 如有旧版连接，先查看恢复预览并确认；陌生或被修改的同名配置不会被覆盖。
4. 按 Codex 自身提示确认启用/信任，方便时重载或完整重启 Desktop。可以稍后完成，不会结束当前任务。
5. 在 Codex 执行多步骤任务，向导会显示等待载入、收到当前会话，最终在真实进度入库后显示 **任务同步已验证**。

没有任务时等待不是错误。检查连接只读状态，不反复改配置。高级选项提供差异、诊断、手动升级和断开；不再要求用户找 AI 或执行脚本修复。

## 修复和变更

- **固定入口**：默认连接使用用户级 Rust Bridge，配置不再跟随ZIP解压目录变化，也不在各项配置内重复写真实数据位置。按版本及内容hash安装运行时，旧进程使用的EXE不覆盖；不允许旧GUI静默降级新运行时。
- **可恢复事务**：Codex配置、active运行时指针、归属receipt使用journal提交与恢复；before/after hash核对，遇并发第三态拒绝覆盖。修复旧prepared状态卡死及缺receipt升级冲突。
- **安全恢复**：完整匹配旧格式的MCP与9项Hook可预览确认后恢复；不按名称自动认领，不删除陌生条目，不叠加疑似修改的旧Hook。
- **MCP事件链路**：默认8项事件直接调用MCP `hook_context`，绕开Windows命令shell AutoRun污染。会话身份由Codex事件模板提供，仍有session token验证和递增revision，不让模型猜身份。
- **真实验证**：当前代次的真实MCP初始化、会话事件及同一报告事件入库后才置为已验证。兼容旧采集器不写新版消费元数据的情况，使用只读数据库事件确认；不会为升级杀死旧worker。
- **观测不干扰业务**：诊断元数据一次原子写入，写诊断失败不会把已经成功持久化的业务事件返回成失败。
- 包含0.8.0候选版的内部标题栏、拖动/双击最大化、SVG窗口控制、离线数据迁移及最新4条叠加测试通知。
- 产品实现仅Tauri/Svelte/Rust，不增加Python运行依赖；此前仓库外临时维护脚本不属于产品，恢复现已内建。

## 支持范围和边界

- Windows x64，需要WebView2与Visual C++ x64 Runtime；便携GUI包未签名，连接组件为用户级部署而非完全零落盘。
- 本轮实际Codex验证版本为 **0.166.0-alpha.5.1**。需要支持MCP-tool Hook的Codex，旧版本和受管理策略限制的环境不保证可用；升级Codex后再连接。
- 默认数据目录及其redirect迁移目标使用固定入口。显式自定义数据root的独立便携实例保留旧command Hook兼容模式，不保证消除其cmd AutoRun问题。
- Codex的SessionEnd不支持MCP Hook，本版该项保留command；AutoRun可能影响其JSON输出解析，但它不承担核心会话绑定及结构化上报，不把Stop/SessionEnd当业务完成。
- 不伪造信任、不改全局审批、不改shell/注册表来绕过Codex；固定路径不承诺以后永不需要正常重新确认。
- 数据迁移仍为离线操作，必须暂停全部生产者；旧0.7采集器不支持暂停时明确拒绝，不能靠重新连接就宣称旧worker已升级。旧数据目录及重定向须保留。
- 验收采用真实Codex、真实Bridge/Reporter/Collector和本地模拟Responses模型；不把模拟模型解释为正式账户/远端模型复验。用户正在工作的正式Codex会话未被终止或改信任。

## 部署位置与清理

默认控制记录：`%LOCALAPPDATA%\CodexFloatboard\control`；连接组件：其`runtime`子目录。任务库仍在原数据目录或用户迁移位置。断开连接只移除严格匹配本工具的Codex配置，不删除任务数据或运行时；在所有旧会话退出前不要手动删除被使用的运行时版本。
