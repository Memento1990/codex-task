# v0.8.0 — 窗口交互、离线迁移与同步诊断

## 更新内容

- 主窗口和完成记录窗口改用内部标题栏，支持拖动、双击最大化 / 还原、最小化和关闭；主窗关闭仍隐藏到托盘。
- 置顶、更多及窗口控制采用统一 SVG 图标，保留键盘焦点和无障碍名称。
- 数据目录入口移入设置，支持打开当前目录、选择空目录迁移并重启看板。
- 迁移使用 SQLite 一致性快照，保留旧数据并写入路径重定向；新版采集器通过 nonce ACK 暂停和连续锁交接切换，失败或迁移者崩溃可恢复。
- 连续点击“测试通知”可叠加不同预览，最多保留最新 4 条；通知窗加载就绪后再投递，修复首次快速点击丢通知的问题。
- 接入状态不再把配置存在当作数据链路已通：区分等待首次 Hook、已收到 Hook、未结构化汇报和处理失败，提供连接诊断。
- 清理旧 Python / Qt 实现及专属测试、依赖和打包脚本，保留 Rust 旧数据兼容夹具。

## 升级

新版仍为 Windows x64 便携版，GUI 与 Reporter 两个 EXE 放在同一目录；需要 WebView2 与 Visual C++ x64 Runtime，未签名、无安装器。

先保留数据备份，将新版解压到独立目录。在新版 **更多 → Codex 接入** 重新连接，正常完成 Hook 信任；完整退出并重新启动 Codex Desktop / CLI，仅新建标签页可能仍复用旧 app-server。更新命令路径可能使原 Hook 需要再次信任，本工具不代写信任记录。

## 数据目录迁移：必须离线

1. 先完成新版接入，再完整退出所有 Codex / app-server 会话及其他看板实例，暂停全部上报。
2. 在 **设置 → 数据目录** 输入一个空的本地绝对路径，确认已退出生产者后执行。
3. 迁移完成后重启看板，再启动 Codex，使所有 Hook / MCP 都使用新版 Reporter。
4. **保留旧目录及其重定向文件，不得删除。** 旧库仅是切换时备份，不持续同步，不能直接覆盖新库回退。

不支持在线迁移、UNC、符号链接/junction、嵌套目录或非空目标。不支持迁移后继续运行不识别重定向的旧版 Hook / Reporter。旧采集器无法安全暂停时拒绝迁移，不会强制结束它。失败的部分目标副本保留，换空目录重试。

## 首次同步排查与未完成验证

本机只读诊断已确认：Codex Desktop 0.165 alpha 新 app-server 能将磁盘上的 9 项 Hook 解析为启用且已信任，Reporter 在隔离目录可登记会话；正式数据目录此前没有 Hook 登记。正在运行的 app-server 启动早于配置更新，完整重启是下一项必要验证，但用户当前有运行中的工作，未执行正式实例重启，因此**不宣称正式会话首次同步已完全恢复**。

另发现本机 `cmd /C` 会受到 AutoRun 输出影响，在 Hook JSON 前增加额外文本；`cmd /D /C` 的隔离实验可输出纯 JSON。但 Codex 选择的 Hook shell 由其运行时控制，本版不擅自改动全局 shell 或注册表；该兼容性问题仍需后续端到端验证。

不要因为没有消息而反复覆盖 Hook 信任、全局审批策略或整个 Codex 配置。先查看接入诊断，区分没有 Hook 与已经收到 Hook 但缺少 MCP 结构化汇报。
