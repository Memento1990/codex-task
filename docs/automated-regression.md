# 本地自动化回归规范

2026-11-04 用户确认：后续开发完成、需要自动化测试时，采用本规范。原生桌面 UI 自动化默认使用 **Win32 独立 Desktop（CreateDesktop）**，不是 Windows 任务视图的虚拟桌面。目标是在不切换用户桌面、不抢系统鼠标键盘、不污染正式环境的前提下验证开发产物。

## 1. 测试分层

- 前端逻辑：在 app/desktop 执行 `pnpm test`。
- 类型及前端构建：`pnpm build`（含 Svelte 检查）。
- Rust 核心/集成：仓库根执行 `pwsh -NoProfile -File ./app/desktop/build-native.ps1 -Phase test-core`。
- 原生内嵌前端构建：仓库根执行 `pwsh -NoProfile -File ./app/desktop/build-native.ps1 -Phase release`，已包含前端检查/构建，不必重复执行。
- 原生 UI：新建独立 Desktop，启动上述开发产物，通过 WebView CDP 驱动真实界面和 Tauri IPC。

按修改范围选择必要测试；桌面交互改动须覆盖相关原生 UI 行为。单元/核心测试可在普通命令环境执行，报告不得声称它们也运行于独立 Desktop。纯文档修改通常不必启动 GUI。

## 2. 固定本轮输入和资源所有权

1. 记录 HEAD、工作区 dirty 状态、测试范围及构建产物路径。存在并发改动时，优先用专属快照/工作区构建；否则记录构建期间源码变化，不将结果作为固定版本验收。
2. 为每轮分配唯一 run ID、证据目录、Desktop 名称和空闲的 loopback 调试端口。不能复用历史停止标记或覆盖旧结果。
3. 检查已有 DEV/正式实例，保留其 PID 和身份；不激活、不关闭、不将其用作测试对象。
4. 先显式构建，再通过官方 `app/desktop/dev-isolated.ps1` 启动，指定 `-Executable <本轮构建>`、`-CodexMode isolated` 和 `-DebugPort <本轮端口>`。先用 `-CheckOnly` 核对目录。
5. wrapper 的默认隔离目录按工作区路径计算，可能被既有 DEV 使用。采用专属测试工作区的官方 wrapper；也可像已验证试验一样，将 wrapper **原样复制**到本轮 fixture 工作区相同相对位置，再调用副本，以获得独立 workspace hash。记录副本来源/一致性和实际 sandbox，不能修改或绕过 wrapper 的隔离检查。
6. 不复制实际 auth/config/token，不操作真实 Codex 索引，不发送真实外部通知，不自动确认接入。测试 fixture 只能落在本轮独立环境中。

## 3. 独立 Desktop 启动与驱动

1. 在当前交互 window station 下调用 `CreateDesktop`，以 `winsta0\\<唯一名称>` 设置 `CreateProcess` 的 `STARTUPINFO.lpDesktop`，启动运行官方 wrapper 的 PowerShell 子进程。保持 Desktop handle 在本轮生命周期中存活。
2. 禁止调用 `SwitchDesktop`、`SendInput` 或其他系统级鼠标键盘注入，不在当前桌面上补跑失败用例。
3. `EnumDesktopWindows` 记录窗口标题、HWND、PID，确认 `[DEV]` 主窗口及功能窗口属于本轮 Desktop。
4. CDP 仅监听 loopback；等待调试端点、page target、前端加载和目标控件就绪，设置超时。不得仅凭固定 sleep 判断启动成功。
5. 通过目标 WebView 的 CDP 操作按钮和读取 DOM，验证真实宿主状态。DOM click 不等于真实指针/焦点验证；截图使用 `Page.captureScreenshot`，明确不是系统桌面截图。
6. 记录未捕获异常和关键失败，保存关键状态截图。具备图像检查能力时检查截图；否则明确标注“已采集，未视觉验收”。

## 4. 基础 UI 回归清单

根据源码和可用 fixture 调整断言，不盲目依赖旧文案：

- 主面板显示 DEV、原生桥接可用、空状态或本轮合成任务数据正确。
- 全部/有卡点/执行中筛选；详情收起与恢复。
- 原生置顶开关双向切换并恢复。
- 设置、Codex 接入、消息通知、版本更新等相关功能窗口能打开、加载、正常关闭，窗口归属正确。
- DEV 更新操作被宿主拒绝；不得执行正式下载、安装或发布。
- 头像球收起及恢复；无新增未捕获 WebView 异常。
- 当前修改涉及的业务流程另加用例。空面板冒烟不能代替任务更新、持久化、数据库修复或通知发送等业务回归。

本机首次试验最终 UI 10/10、前端 36/36、Rust 139/139 通过；这些是历史基线，不是后续必须保持不变的用例数量。

## 5. 失败处理与覆盖边界

- 区分产品缺陷、断言错误、启动竞态和环境限制。修正测试后保留首轮结果并重新执行，不静默删除失败或跳过用例凑全绿。
- 首次试验发现 DEV 更新页仍显示常规检查按钮，宿主会拒绝操作。未来若界面改进，更新断言；不能因普通按钮存在就认定保护失效，也不能只看文案认定保护有效。
- CDP 无法完整验证真实输入、系统焦点/前台争抢、托盘、窗口拖动、跨屏、遮挡及系统截图。相关需求应报告为覆盖缺口；如必须在可见交互环境补测，先获得用户授权，不能自行切换桌面或另启替代环境。
- 不支持或未执行的项目必须如实说明，不计为通过。无法创建独立 Desktop 或连接 WebView 时，报告具体阻塞，不默默回退到当前桌面。

## 6. 清理和交付

- 优先通过本轮 GUI 的“退出看板”等正常退出路径关闭，关闭到托盘不算退出。
- 只关闭经 Desktop、PID、可执行文件、命令行/沙箱核实为本轮所有的资源；禁止按名称批量结束 GUI/WebView/Reporter/Codex。
- 等待退出，释放自建 Desktop 和进程句柄，确认本轮调试端口不再监听。超时或残留要报告，不强行清理他人实例。
- 保留测试证据与独立沙箱，不删除既有 DEV/正式数据。清理目录前必须验证绝对路径和所有权。
- 汇报各层通过/失败数量、实际覆盖、未测项、发现及清理状态。保存命令/退出码、构建日志、初始与最终结果、桌面/PID 归属和截图。
- 测试授权不包含 commit、push、GitHub Release 或正式安装授权。

原始试验记录和脚本位于 `artifacts/win32-desktop-20261104/`（本地证据，不作为稳定测试入口）。其中脚本带有固定端口、停止标记和本轮路径，**不能直接作为后续通用运行器重复执行**；复用前须按本规范参数化、使用唯一资源并校验清理。
