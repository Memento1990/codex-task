# 一键修复并重启

## 使用方式

设置中的「修复并重启」只需要一次确认。应用内部抢救能够读取的任务，在独立数据目录中校验，正常退出看板后再切换并重启。不会要求用户手动选择数据库、复制文件或运行 BAT。

- 只有实际抢救到任务且数据库完整性与任务结构校验通过，才允许启用新目录；无法读取任务时不会用空库冒充成功。
- 原数据库及其日志保留，修复只针对副本。部分历史事件与耗时可能无法恢复，界面不会补造历史。
- 重启后必须确认使用新目录、任务可读、上报收集器健康，才显示完成。数据切换后重启或健康确认失败，不回滚已可能接收新上报的新库；可正常重新打开看板继续确认。
- 如仍有无法协调暂停的旧版上报程序，操作会阻止切换并重新打开原看板。等待旧会话正常结束后重试，不需要强杀进程。

## 安全边界

执行器使用与看板同版本目录中的 Reporter，通过进程句柄核对并等待原看板正常退出。后台修复需要独占修复/迁移锁，以及新协议收集器提供的身份、心跳与暂停确认；源数据库文件同时持有拒绝写入与删除的只读句柄。执行器重新抢救并校验后才写入持久化重定向。

切换保留原入口与历史收集器身份，迟到的旧入口上报仍由同一收集器路由到新目录。已确认或不确定投递的通知不会因恢复任务历史而自动重发；通知基线会重新建立，不把抢救出的历史任务当作新变化群发。

这不是任意第三方数据库写入器的迁移协议。当前文件占用、未知或旧版收集器不能证明已暂停时应拒绝操作；不能保证未来绕过应用直接打开旧路径的外部程序会遵守重定向。

## 本地验收

按 `docs/automated-regression.md` 执行前端、核心和原生构建测试；在独立 Win32 Desktop、独立 DEV 数据和 Codex 配置中通过真实 Tauri 界面验证修复、重启、后续旧入口上报及普通重启。不得以空库冒烟代替损坏库业务测试，也不得将本地验收视为发布、安装或修改正式数据的授权。
