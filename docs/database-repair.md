# 一键修复并重启

## 使用方式

设置中的「修复并重启」只需要一次确认。应用先在独立副本验证完整性、任务结构和真实应用读取，再完整保存数据库与已提交日志，正常退出看板后切换并重启。不会要求用户手动选择数据库、复制文件或运行 BAT。

- 只有完整副本含实际可见任务且校验通过，才允许启用新目录；无法读取任务时不会用空库冒充成功。
- 健康副本保留全部事件、计时依据和历次完成归档，不再无条件重建为只有当前任务的空历史库。副本封存不运行业务迁移。
- 损坏副本仍可尽力生成任务快照抢救报告，明确标记 `partial_recovery` 及未恢复的历史、耗时；本版本不会自动启用部分副本，也不提供绕过保护的确认入口。原数据库、日志与抢救副本均保留。
- 重启后必须确认使用新目录、任务可读、上报收集器健康，才显示完成。数据切换后重启或健康确认失败，不回滚已可能接收新上报的新库；可正常重新打开看板继续确认。
- 如仍有无法协调暂停的旧版上报程序或文件身份分裂，操作会阻止切换。关闭旧会话不保证后台采集器退出；请保存工作并正常重启 Windows，再打开看板重试，不强杀 Codex 或 Reporter。
- 最新失败尝试单独记录并展示具体原因；此前已提交事务的身份和结果仍保留，不会用旧“完成”状态掩盖新的准备失败。

## 安全边界

执行器使用与看板同版本目录中的 Reporter，通过进程句柄核对并等待原看板正常退出。后台修复需要独占修复/迁移锁，以及新协议收集器提供的身份、心跳与暂停确认；源数据库文件同时持有拒绝写入与删除的只读句柄。执行器在已验证暂停下重新生成完整副本并校验，禁止从完整恢复降级为丢失历史的部分抢救，随后才写入持久化重定向。旧版本预备的部分恢复事务也必须重新准备，不能直接应用。

文件名与新路径锁不是唯一写入者的证明。旧进程仍持有已替换的主库或锁文件，同时共享当前 WAL/SHM 时，文件对象身份检查必须阻止修复；不能以新锁可获取、心跳版本较新或离线副本可读为由放行。

当前 Reporter 的主库与进程锁在持有期间拒绝删除共享，并在读写/循环前核对卷与文件索引。打开 Store、启动采集器和授权修复前，只查询相关 Reporter 的磁盘句柄元数据；不会读取外部数据库内容、释放他人锁或结束他人进程。对已删除或改名备份后仍共享 WAL/SHM、又缺少当前主库与锁成对身份的进程保守拒绝；完整持有当前主库与锁时，无关已删除临时文件不构成冲突。此检查不是任意第三方写入者的证明，详见 [运行时诊断](database-runtime-diagnosis.md)。

切换保留原入口与历史收集器身份，迟到的旧入口上报仍由同一收集器路由到新目录。已确认或不确定投递的通知不会因恢复任务历史而自动重发；通知基线会重新建立，不把抢救出的历史任务当作新变化群发。

这不是任意第三方数据库写入器的迁移协议。当前文件占用、未知或旧版收集器不能证明已暂停时应拒绝操作；不能保证未来绕过应用直接打开旧路径的外部程序会遵守重定向。

## 运行时诊断

GUI 同步启动检查仅在当前版本或已驻留更新版本采集器心跳为 `ok`、Store 实际打开并读取任务成功后返回就绪。`starting`、陈旧心跳、存储错误或子进程已经退出均不视为启动成功。Hook/MCP 在独立后台检查进程中执行相同安全检查，以免超过命令 Hook 的 3／5 秒响应期限；协议回复只证明邮箱接收或绑定完成，不代表采集就绪。后台进程不会继承协议管道，避免延迟 EOF。迁移/修复在持有迁移锁时使用独立的“启动后等待暂停凭据”路径；它不等待被该锁阻止的存储就绪，也不升级或终止既有采集器，仍须验证带 nonce 的新鲜暂停确认。

正式目录的诊断位于 `%LOCALAPPDATA%/CodexFloatboard/control/runtime/`；独立测试目录位于其自身 `runtime/`。`storage-last-error.json` 保存最近快照失败，`worker-start.json` 保存启动子进程提前退出，`worker-last-exit.json` 保存正常退出原因或错误阶段，`worker-check.json` 保存最近一次后台检查结果及启动/管道隔离失败阶段。`health.json.diagnostic` 同时提供当前采集错误。仅记录固定阶段、SQLite 主/扩展码、Win32 数值码、PID、版本和时间，不保存 SQL、任务内容、凭据或底层私密报错文字。诊断目录本身不可写时无法保证持久化，不能以文件缺失认定没有故障。

Windows 瞬时读句柄可能阻止 JSON 原子替换；仅对系统码 5/32/33 限时重试 250ms，期间保留旧值。超过上限仍失败并记录阶段，不以忽略写入错误假称心跳/暂停确认成功。

## 本地验收

按 `docs/automated-regression.md` 执行前端、核心和原生构建测试；在独立 Win32 Desktop、独立 DEV 数据和 Codex 配置中通过真实 Tauri 界面验证修复、重启、后续旧入口上报及普通重启。不得以空库冒烟代替损坏库业务测试，也不得将本地验收视为发布、安装或修改正式数据的授权。
