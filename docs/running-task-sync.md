# 首次接入时同步正在执行的任务

## 不等于扫描历史

看板不读取原始聊天或最近会话索引来猜任务，也不会向正在运行的 Codex 自动发送消息、转向或中断。接入写入配置不代表已有 app-server 已加载新工具。

## 操作

1. 在 Codex 原生界面正常启用、信任连接。旧会话须已加载对应 MCP 与 Hook；按当前客户端支持的能力正常重载。若不支持或任务不便打断，稍后处理，不强制退出。
2. 看板“Codex 接入”页点击“复制同步指令”。
3. 在原任务会话自然停顿时发送；多个会话分别发送。已有 UserPromptSubmit Hook 为该会话提供真实绑定和 revision，再由模型使用 report_progress 上报当前完整快照。
4. 等待真实汇报入库。刷新状态只读取回执，不触发同步；复制成功不改变验证状态。

只补当前可确认的标题、清单、卡点、验收证据，不补造接入前的历史或计时。单个已验证回执不表示所有运行中会话均已同步。没有有效工具或绑定时，指令要求说明不可用，不猜 token、不手动模拟 Hook、不改配置。

## 证据边界

当前 HTTP MCP/OAuth 与 Hook 的隔离验证使用 Desktop 实际采用的 Codex 二进制；结果见 `artifacts/agent-runtime-20261109/transport-current-binary.log`。没有验证所有客户端都能热加载已有会话，另起 app-server 不能替代重载既有正式进程。

## 版本显示

主窗口页脚和更新页初始值共用 GUI 包版本元数据，更新页后续快照由 GUI 内的更新服务提供。Agent 身份单独返回协议、schema、profile 和数据库身份。打包时逐个核对八个运行程序的版本、公钥和更新协议。
