三套共同解决的四个问题

  • 信息密度：三套都先把"总数、卡点数、待确认数"提炼成一排数字或一条分布带， 再进入明细。现有实现没有这个层级。
  • 功能深埋：A 用底部完成带 + 工具栏；B 用右侧常驻介入栏；C 用常驻命令条 + ⌘K。 接入、通知、设置、完成记录不再只在"更多"里。
  • 视觉专业化：统一暗色工程终端底座。A 偏表格/监控台，B 偏编辑/叙事， C 偏追踪/监控。三者都不再是 Office 插件的气质。
  • 交互模型：三种不同的信息几何，不是同一套页面换顺序。

共同保留的产品契约

  • 贴边头像球三套都重做了，但都保留"拖到屏幕边缘收起"的行为与悬停摘要。
  • 浮窗通知的常驻卡点 / 定时普通通知规则不变，只是挂到新的视觉语言下。
  • 独立工具窗（设置 / 接入 / 通知 / 更新 / 修复）结构与文案语义不变。
  • 数据与隐私边界：不新增动态流水数据源，时间线只由已有的计时字段还原。
  • 技术栈：纯 HTML/CSS/JS，无框架、无构建步骤；移植到 Svelte 5 时逐组件替换即可。
所有界面均为原型，数据为合成数据，不代表真实安装或任务。三套原型中，窗宽 980 对应建议放宽后的默认尺寸， 窗宽 392 为保留的最小宽度；两档都实现了，可直接对照。
