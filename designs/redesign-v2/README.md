## 三套方案的一句话区别

| | 第一性问题 | 信息几何 |
|---|---|---|
| **A 巡检矩阵** | 现在整体什么状况？ | 行＝任务，列＝属性，一张表 |
| **B 聚焦时间线** | 这个任务进行到哪了？ | 纵向＝时间，一次一个任务 |
| **C 并发泳道** | 它们之间怎么交错？ | 横向＝时间，多任务并排 |

三套不是同一批页面换顺序，而是三种不同的信息组织方式。详见 `index.html` 里的差异矩阵。

## 已确认的需求前提

- **交付形态**：可点击 HTML 原型，纯静态，无框架、无构建步骤。
- **覆盖范围**：全部界面，含独立工具窗（设置 / 接入 / 通知 / 更新 / 修复）。
- **尺寸约束**：默认放宽到约 980×680，最小仍保 392×570 且保证窄态可用 —— 两档都已实现。
- **视觉底座**：暗色工程终端质感（等宽字体承载数据、细描边、低饱和强调色）。
- **差异化轴**：交互模型与视觉语言同时不同。
- **重点**：全局总览优先，卡点从"任务的一个页签"上升为可扫读的顶层信息。
- **贴边头像球**：保留形态，重做信息表达，三套各给了不同做法。

## 覆盖的功能清单（三套均完整实现）

多任务汇总与筛选、结构化清单、卡点四要素、验收证据、自然耗时、贴边头像球与悬停摘要、
完成记录独立窗口、浮窗通知规则、设置与数据目录迁移、Codex 接入三步向导与分层证据、
消息通知三渠道与发送记录、版本更新、数据库修复。

## 明确没有做的事

- 没有新增"动态流水"数据源。B 的时间线只由已有的 `startedAt / endedAt / openedAt / at`
  字段还原，不违反现有"不保存动态流水"的边界。
- 没有改动 `app/desktop` 下的任何文件，也没有触达 `%LOCALAPPDATA%` 下的正式安装。
- 原型里的开关、折叠、展开、命令面板都是真实可交互的，但**不写任何数据**。

## 选定方向之后

推荐路径：先选定一套，我按 `shared/data.js` 的真实模型把它拆成 Svelte 5 组件
（`App.svelte` 的视图层替换，`host.ts` 的 bridge 调用与 `model.ts` 的类型不动），
再在隔离 DEV 环境跑一遍回归。视觉语言若用到少量 CSS 变量与原生控件样式，
不需要引入 UI 框架；如果确实需要组件库，届时只引入样式级别的部分。
