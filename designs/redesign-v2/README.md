## 三套方案的一句话区别

| | 第一性问题 | 信息几何 |
|---|---|---|
| **A 巡检矩阵** | 现在整体什么状况？ | 行＝任务，列＝属性，一张表 |
| **B 聚焦时间线** | 这个任务进行到哪了？ | 纵向＝时间，一次一个任务 |
| **C 并发泳道** | 它们之间怎么交错？ | 横向＝时间，多任务并排 |

三套不是同一批页面换顺序，而是三种不同的信息组织方式。详见 `index.html` 里的差异矩阵。

## 已确认的需求前提

- **交付形态**：可点击 HTML 原型，纯静态，无框架、无构建步骤。
- **覆盖范围**：全部界面，含独立工具窗（设置 / 接入 / 通知 / 更新 / 修复）。
- **尺寸约束**：默认放宽到约 980×680，最小仍保 392×570 且保证窄态可用 —— 两档都已实现。
- **视觉底座**：暗色工程终端质感（等宽字体承载数据、细描边、低饱和强调色）。
- **差异化轴**：交互模型与视觉语言同时不同。
- **重点**：全局总览优先，卡点从"任务的一个页签"上升为可扫读的顶层信息。
- **贴边头像球**：保留形态，重做信息表达，三套各给了不同做法。

## 可操作的 Mock 闭环

外壳右上角选择常规、卡点已解除、待确认、缺失 / 部分计时、失败与重试、空数据、取消 / 中断、
55 条完成记录。三套使用同一初始数据，各自独立保存操作。

- 搜索任务、卡点、项目并筛选状态；A 行内展开、B 胶片切换、C 泳道和红标下钻。
- 详情包含清单、卡点四要素、证据预览、任务推进。开放卡点阻止完成；解除须填验证结果，
  自动生成模拟证据。待确认须确认后继续，全部步骤完成且有证据才归档，可重新打开。
- `Ctrl/⌘ K` 搜索任务、项目、功能与动作；↑↓ 选择、Enter 执行、Esc 关闭。
- 证据支持预览、复制引用、添加与输入校验，不访问真实文件或样例 URL。
- 完成记录可搜索、点击详情、底部分页，支持 20 / 50 / 100。
- 设置、主题、通知秒数、头像摘要方式可变更；迁移路径校验后走预览 → Dry run → 确认执行。
- 接入按配置 → 组件回执 → 会话事件 → 任务汇报分步模拟，支持冲突、部分配置、错误、
  诊断、同步指令与断开 / 恢复，不把旧回执当实时在线。
- 微信扫码 / 解绑，企微和飞书 Webhook 校验 / 保存，渠道启停、测试、订阅、记录和失败重试。
- 更新有检查、下载进度、取消、安装确认、模拟重启；修复有预览、Dry run、确认、重建和验证结果。
  重置场景后，旧异步操作不会污染新状态。
- 头像球动态显示进度与卡点，支持摘要模式、悬停、拖动左右吸附、点击恢复。
  置顶、最小化、窗口大小和关闭都只模拟页面状态。

## 明确没有做的事

- 没有新增聊天或工具动态流水。证据时间表示“首次记录”，未知值不补造；步骤支持累计计时、
  `partial` 与多段 `segments`，等待用 `waitingSince`。实际可提供性见 [DATA-CONTRACT.md](DATA-CONTRACT.md)。
- 本目录的模拟操作不调用真实宿主，不触达正式安装或正式数据；产品移植另见下节。
- 操作只更新页面内存和本标签页 `sessionStorage`，刷新可恢复；关闭标签页结束。
  “重置”只恢复当前方案的初始 Mock，不影响其他方案。
